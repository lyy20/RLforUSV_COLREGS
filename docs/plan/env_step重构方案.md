## 二、能省多少：**给上界与下界，不给「保证 3 倍」**

| 界 | 含义 | 数值 |
| --- | --- | --- |
| **理论上界** | 两大块完全消失 | 7.4 → ~0.2 ms（不可能） |
| **现实区间** | 逐实体循环向量化典型收益 2–4× | **7.4 → 2.5–4.0 ms**（**省 46–66%**） |
| **可承诺下界** | 若达不到就回滚，不交付 | **步耗时降低 ≥30%**（7.4 → ≤5.2 ms） |

**为什么不承诺更多**：
1. 一部分成本是 numpy 调用开销，向量化能削但削不到零；
2. **训练总加速 ≠ 步加速**——`network_update` 占 5%、GPU 部分不缩；
3. 因此**端到端现实预期：1.4–2.0×**（2.97 → ~1.5–2.1 s/回合），不是 3×。

## 四、⚠️ 顺带发现并修复的严重问题：环境此前不可复现

`usv_tracking_base.py:1545` 原为 `np.random.default_rng()`（**无种子**）抽样船只身份
⇒ **同一配置、同一种子，每次运行船型不同** ⇒ 轨迹不可复现、**3 seed 对比会被混淆**。

**修复**：改为从**已播种的全局 RNG** 取种子。
**验证（三跑一摘要）**：

| 运行 | digest |
| --- | --- |
| 原版 run1 | `05dec3c7e97ae70aec059b671c32d566` |
| 原版 run2 | `05dec3c7e97ae70aec059b671c32d566` |
| 副本 | `05dec3c7e97ae70aec059b671c32d566` |

⇒ **已可复现**，且副本与原件数值级一致（等价性探针可用）。
（注意：需 `PYTHONHASHSEED=0`，否则进程间 hash 随机化仍会引入差异。）

## 六、执行纪律

1. **每次改动后必须跑 digest**：一致才继续，不一致立刻回退；
2. 计时必须在**空机**做（本机此前多次被训练进程污染）；
3. 原版仓库 **只做可回滚的提交**，重构一律在副本；
4. 最终对比：两个项目跑**同一配置同一实验**，看 digest 是否一致 + 墙钟差异。
