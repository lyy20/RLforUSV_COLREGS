# 会遇生成：根因修复的原理与落地（重瞄 / 自适应生成）

> 2026-10-13 · 回答一个问题：**为什么重瞄/自适应是根因修复，而不是往缩小中的样本池里加水？**

---

## 0. 先纠正一处错误诊断（我上一轮说错了）

上一轮我说「会遇是按本船静止设计的」。**读过代码后更正**：

| 位置 | 代码 | 真实假设 |
| --- | --- | --- |
| `encounter_wrapper.py` L424 | `psi_s = atan2(route)` | 本船沿**目标方向**航行 |
| **L425** | **`u_s = world.agent_nominal_speed`** | 本船以**巡航速度**（≈5.9 m/s）航行 |
| L46-59 | `v_s = u_s·[cosψ_s, sinψ_s]`；`p_o = p_s + d·n̂ − v_rel·T` | 在此假设下反推目标，使 DCPA=d、TCPA=T |

所以设计本身是**合理的**：它对「直线巡航的本船」是正确的。问题在于：**这个假设在真实回合里被破坏**，而破坏的代价**被 DCPA 的尺度放大了**——见第 2 节。

---

## 1. 问题的数学形态

设相对位置 r = p_o − p_s，相对速度 v_rel = v_o − v_s。规则引擎判定「存在让路义务」的前提之一是：

```
TCPA = −(r·v_rel)/|v_rel|²   落在 [60, 300] s
DCPA = |r + v_rel·TCPA|        落在 [0.01, 0.06] km  (10~60 m)
```

生成器在**回合开始时**选取 p_o 与 v_o，使**在它假设的 v_s 下**这两个式子成立。
⇒ 只要真实的 v_s(t) 与假设的 v_s 不一致，**这两个式子就不再成立**。

**关键量纲对比（这是全部问题的核心）**：

| 量 | 数值 |
| --- | --- |
| 设计的 DCPA（要保住的精度） | **10 ~ 60 m** |
| TCPA（要等的时间） | **60 ~ 300 s** |
| 本船巡航速度 | 5.84 m/s（实测） |
| 目标速度 | 1 ~ 2 m/s |
| **假设偏差每 1 s ⇒ 位置误差** | 最多 **5.9 m** |
| **假设偏差 20 s ⇒ 位置误差** | **≈ 118 m，远大于设计的 10~60 m** |

⇒ **只要假设轨迹与真实轨迹差 20 秒的位移，设计好的会遇就彻底失效。**
这就是为什么它**不是调参问题**：精度要求（10~60 m）比系统的时序不确定性（百米级）**小一个数量级**。

## 2. 假设具体是怎么被破坏的（三个已定位的破坏源）

| # | 破坏源 | 机制 | 量级 | 证据 |
| --- | --- | --- | --- | --- |
| **1** | **启动加速段被忽略** | 设计假设立刻 5.9 m/s，实际本船**从静止起步**，约 40~50 步才到巡航 | 位移亏损 ≈ 0.5×5.9×45 ≈ **130 m** | 实测 reset 时 u=0.000、t≥49 后 u=5.824 |
| **2** | **策略不走朝目标的直线** | 学习后的策略会转向/绕行/甚至**远离目标**（A2 目标距离 1.10 → 1.116 在增大） | 偏差随 TCPA 线性放大（60~300 s ⇒ 数百米到公里级） | TB：A2 距离单调增大 |
| **3** | **策略越学越飘（躺平）** | 惩罚项让策略选择不出界、不接近 ⇒ 更少走进被设计的会遇 | 发声率 18.7% → 2.75% | TB：A1/A2 发声率与修正幅度双降 |

> **注意破坏源 1 是系统性的、与策略无关**：即使策略完美地朝目标直线开，也仍然会偏 ~130 m。
> 这说明**光靠 A/B 两个杠杆（重采样/造态）永远修不好**——因为它们复用的是**同一套已经错了的布置**。

## 3. 直白解析：靶场比喻

| 做法 | 比喻 | 为什么行 / 不行 |
| --- | --- | --- |
| **现状** | 教官按「你以 5.9 m/s 直线冲刺」预判，把靶子摆在你**未来会路过**的位置；结果你起步慢、还拐了弯 ⇒ **靶子打空了** | 布置是一次性的、且基于假设轨迹 |
| **杠杆 A（重采样）** | 把**同一个已经打空的靶**多摆几遍，让你多打几次 | 靶位还是错的，练不到 |
| **杠杆 B（造态）** | 从**别的靶场**再搬几套靶过来 | 靶位仍然是别人的假设，不跟你的实际轨迹 |
| **根因修复（重瞄）** | **让靶子会飞**：它每时每刻重新解算自己的速度，**始终维持在「再飞 T 秒会与你擦身 d 米」的位置** | 只要你在动，**冲突就被保证发生**——不管你怎么走 |
| **根因修复（自适应生成）** | 让**教官看着你的水平出题**：你越会躲，题就越贴着你出 | 训练分布**跟着策略走**，不随训练塌缩 |

## 4. 重瞄的闭式解（可直接实现，不需要学习）

**已知**：相对位置 r = p_o − p_s（当前实测）；本船速度 v_s（当前实测）；期望 d* 与 T*。
**求**：目标应有的速度 v_o，使**当下这个瞬间**的相对运动满足 DCPA=d*、TCPA=T*。

```
第一步：由 DCPA 定义解出相对速度大小
   |r + T*·v_rel| = d*   且   r·v_rel = −T*·|v_rel|²
   联立 ⇒ |r|² − T*²·|v_rel|² = d*²
   ⇒ |v_rel| = sqrt(|r|² − d*²) / T*        ← 闭式

第二步：分解方向
   r̂ = r / |r|
   沿 r 分量  a = −T*·|v_rel|² / |r|
   垂直分量  b = sqrt( max(|v_rel|² − a², 0) )
   v_rel = a·r̂ ± b·n̂       (n̂ ⊥ r̂，两个解任取其一)

第三步：还原目标速度
   v_o = v_s + v_rel
   并夹到目标能力范围：|v_o| 在 [u_min, u_max] 内，转向速率不超过上限
```

**这就是重瞄的全部数学：每 K 步用当前实测的 r 与 v_s 重算一次 v_o。**
每步计算量是常数级（几次乘加），**对训练速度基本无影响**。

**若算出的 v_o 超出目标能力**（例如需要它 12 m/s 才追得回来）⇒ 说明这次会遇**已经救不回** ⇒ 标记失效，**触发重新布置**（`relocate()`）。

## 5. 为什么这是根因修复（与 A/B 的本质差别）

设训练时的状态分布为 μ_t，当前策略为 π_t；定义义务区域 Ω = 规则引擎会发声的状态集合，
于是发声率 = P(s ~ μ_t 且 s ∈ Ω)。

| 做法 | 改的是什么 | 数学效果 | 随训练会怎样 |
| --- | --- | --- | --- |
| **杠杆 A 重采样** | 样本的**权重** | 在**固定 μ** 上重加权 | μ 不动、π 在动 ⇒ 交集仍会塌缩 |
| **杠杆 B 设计态** | 样本的**来源**（外部固定分布 ν） | 训练分布 ≈ μ + ν | ν 也不动 ⇒ 交集仍会塌缩 |
| **根因修复** | **生成分布本身** | **μ_t = G(π_t)**，且带接受约束：义务密度(π_t, 场景) ≥ q 才接受 | 交集**有下界，由构造保证** |

**一句话**：

> A 和 B 是在**给定的分布里取样本**；根因修复是把**分布本身变成策略的函数**，并把「发声率」从**涌现出来的结果**改成**生成时必须满足的约束**。

所以它不是加水，而是**换掉了水源**：从「一次性摆好的固定靶场」换成「跟着你跑的靶子 + 看着你出题的教官」。

## 6. 落地：三步，按改动量从小到大

### P0（最小改动，一处，先做这个）

**问题**：`relocate()` L425 用 `agent_nominal_speed` 假设本船立刻巡航，而本船实际从静止起步。

**做法（二选一，建议 A）**：

| 方案 | 具体 | 代价 |
| --- | --- | --- |
| **A（推荐）** | **先空跑 N≈40 步让本船达到巡航，再调用 `relocate()`**（本船满推力直行，这几步不参与学习） | 每回合多 40 步布置开销 |
| B | 解析补偿：u_s_eff = u_nominal·(1 − t_accel/(2T)) | 近似，不如 A 干净 |

**预期**：一次性消掉约 130 m 的系统性偏差 ⇒ 发声率应**显著回升**（这是最便宜的一次验证）。

### P1（重瞄，核心）

**位置**：`_mode_velocity()`（L316）**已经是一个逐步调用的钩子**（`_enforce_encounter_motion()` L377 每步都调它）⇒ **加一个新模式 reaim 即可**，不需要动框架。

```
每 K 步（K = 10~25）：
  用第 4 节闭式解算出 v_o_target
  若 |v_o_target| 或转向速率超限 ⇒ 标记 encounter_expired = True
  否则平滑过渡到 v_o_target（限制加速度，避免瞬移式作弊）
每步：仍由 _mode_velocity 输出当前 v_o（保持逐步运动授权不变）
```

**护栏（很重要，避免被质疑作弊）**：

1. **只用可观测量**：r 与 v_s（相对位置与本船速度）——都是真实传感器能得到的；**不许用策略内部状态或未来信息**；
2. **限制执行能力**：目标速度上限、转向速率上限、加速度上限（复用 `dynamic_obstacle_*_speed`）；
3. **重瞄有延迟**：每 K 步才更新一次，模拟对方也在反应，而不是每毫秒全知。

### P2（自适应生成，长期）

| 部件 | 做法 | 文献对应 |
| --- | --- | --- |
| **场景评分** | 对每个生成的会遇打一个**当前策略下的义务密度**分（用规则引擎在**预测轨迹**上评估，或短 rollout） | PLR 的学习价值 |
| **优先级缓冲** | 维护场景池，**优先重采样高分场景**，同时保留一定比例**全新随机场景**（防塌缩） | Prioritized Level Replay |
| **对抗生成（可选）** | 让生成器的目标是**最大化义务密度 / 最小化策略在该场景的收益** | PAIRED（regret 目标） |
| **接受判据升级** | 把 `_verify_placement()` 现在的判据（实现 CPA ≈ 设计 CPA）**换成义务密度 ≥ q 且有效发声率 ≥ p** | 我们的直接需求 |

> 注意：`_verify_placement` 我们已因**耗时**关掉（166 步 rollout ≈ 1.37 s/回合）。
> 但**义务密度的接受判据可以不用 rollout**：规则引擎是**解析函数**，可以直接在预测轨迹上采样若干时刻求值 ⇒ 成本近似为零。

## 7. 必须守住的三条护栏（否则论文会被质疑）

| 护栏 | 原因 | 做法 |
| --- | --- | --- |
| **评估必须独立** | 训练场景自适应了，评估再自适应就**无法声称泛化** | **训练用自适应生成；评估用固定场景集**（内化检验也用固定集） |
| **难度要有上限** | 对抗生成会把环境推到学不会的边界，导致训练不稳 | 义务密度上限、DCPA 下限、保留一定比例简单/新鲜场景 |
| **真实性要说清** | 会读心的靶子看起来像作弊 | 限定可观测量 + 执行能力上限 + 更新延迟；论文里明确写成**训练期的对抗式场景生成器** |
