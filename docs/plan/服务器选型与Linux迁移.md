# 服务器选型与 Linux 迁移

> 抓价日期：2026-10-10（全部为当日实测抓取，非记忆值）。价格会变，**下单前以平台现价为准**。
> 本文只解决一件事：**在保证能跑通、稳定跑完的前提下，把 4.2M 回合的训练尽快跑完，且不花冤枉钱。**

## 0. 一句话结论

**首选 优云智算(compshare)：2×RTX4090 / 28C / 96G，按量 4.06 元/时**；先花 5 块钱买 1×4090/16C/64G 跑 2 小时做标定，再决定正式机型。
总预算落在 **2500–5000 元**、墙钟 **30–50 天**；**钱不是主要变量，墙钟才是**——所以选"能随时升降配、按秒计费、CPU 核数写得清清楚楚"的平台。

## 1. 这个项目到底吃什么资源（实测锚点，不是直觉）

| 实测项 | 数值 | 出处 |
| --- | --- | --- |
| 1 进程（parallel_envs=36） | **2.25 s/回合 → 0.444 回合/s** | 本地 bench（20 逻辑线程） |
| 1 进程（parallel_envs=12） | 2.94 s/回合 | 同上 |
| 2 进程（各 18 workers） | 3.10 s/回合/进程 → **0.645 回合/s** | 同上 |

**读数**：workers 从 12 加到 36 只快 31%，说明**瓶颈不是 worker 数，而是每个训练进程内部那条串行主链**（主进程前向/回传、管道收发、日志）。
**推论（选型的核心）**：
- 想更快，只能**增加并发训练进程数**，不能靠加 workers；
- **每个训练进程配 ~10 个逻辑核就够**（更多核不涨吞吐）；
- 因此 **核数需求 ≈ 10 × 目标并发进程数**；
- **进程数一进程约 4–5 GB 显存**：本地 4070（12 GB）2 进程 OK、**3 进程 CUDA 报错** → 24 GB 卡预计 4–5 进程（**必须实测，见 §4**）。

> 结论：**显卡不需要贵，但"每 GB 显存能跑几个进程"和"CPU 核数"决定一切。**
> 4090 24 GB 是性价比拐点；A100/H100 对本项目是纯浪费（模型是几层 MLP）。

## 3. 成本模型与总账

训练总量 = 阶段一 12×100k + 阶段二 6×500k = **4.2M 回合**。

> 1 回合 = `episode_length` 600 步 × `parallel_envs` 并行环境（`main.py:2465` 的 `for episode_t in range(episode_length)`）。

模型：`吞吐 ≈ 0.40 回合/s × 并发进程数`（略低于实测 0.444，留保守余量）；价格用按量价。

| 机型 | 价格(元/时) | 建议进程数 | 吞吐(回合/s) | 墙钟 | 总价 |
| --- | --- | --- | --- | --- | --- |
| 1×4090 / 16C | 2.15 | 1 | 0.40 | 121 天 | 6250 元 |
| 1×4090 / 16C | 2.15 | 2（16C 紧） | 0.70 | 69 天 | 3570 元 |
| **2×4090 / 28C** | **4.06** | **3** | **1.20** | **40.5 天** | **3946 元** |
| 2×4090 / 28C（抢占） | 2.69 | 3 | 1.20 | 40.5 天 | 2615 元 |
| Vast.ai 128vCPU / 1×4090 | ≈6.1 | 4（显存限） | 1.60 | 30 天 | 4392 元 |

**这就是本次选型最重要的一句话：总价在 2600–4400 元之间几乎不动（因为价格≈核数×单价，吞吐≈进程数，两者同比例），真正的差别是"30 天还是 120 天"。所以不要为了省几百块去买小机器——买"够并发"的机器。**

## 4. 购买顺序（先花 5 块钱标定，再花 4000 块）

1. **先买 1×4090 / 16C / 64G 按量（2.15 元/时）**，跑 `bash scripts/server_bootstrap.sh`，约 2 小时、**成本 ≈ 4.3 元**：
   - 确认 Linux 能跑通（§6 清单）；
   - 跑 `bash scripts/bench_server.sh`，拿到**本机真实标定**：1/2/3 进程 × 8/12/16 workers 的回合吞吐 + 峰值显存。
2. 用标定值反算：`需要进程数 = ceil(4.2e6 / 目标天数 / 86400 / 单进程吞吐)`，再 `核数 = 10 × 进程数`，选机型。
3. 正式跑用**按量**（随时升降配、关机不计费）；阶段一试**抢占**可省 ~35%（代价：可能被回收 → 必须依赖断点续跑）。
4. 包月：14C/32G = 1154.64 元/月 ≈ **1.60 元/时**，比按量 1.92 便宜 17%。**只有确定连续跑满 30 天才划算**，否则按量更省。

## 5. 省钱的四个杠杆（按收益排序）

| 杠杆 | 收益 | 代价 / 前提 |
| --- | --- | --- |
| **① 早停**：阶段二不必跑满 500k | 最大，可省 20–30% | **必须在开跑前登记停止判据**（例如"教师发声率与成功率连续 20k 回合无改善"），否则是事后挑数据 |
| **② 阶段一降到 40k 回合** | 1.2M→0.48M（总量 −17%） | 阶段一只用于"筛选出前 2 名"，判据（教师发声率 ≥10%、loss 有限、出界率 ≤5%）在 40k 已可读 |
| **③ 抢占式** | −35% 单价 | 需先验证断点续跑（§6.4） |
| **④ 包月** | −17% 单价 | 需连续跑满 30 天 |

> ①② 是"预算决策"，不是"技术决策"——**由你拍板**；我不会替你缩小实验规模。

## 6. Linux 迁移清单

### 6.1 已核实、必做的（不改代码）

| # | 项 | 证据 | 动作 |
| --- | --- | --- | --- |
| 1 | **日志根目录默认是 Windows 路径** | `utilities/paths.py:15` → `D:\USV\logs` | `export USV_LOG_ROOT=/root/USV/logs`（**必须**，否则会在当前目录建一个名为 `D:\USV\logs` 的怪目录） |
| 2 | **线程超订** | `main.py:2093` 只对主进程 `torch.set_num_threads(parallel_envs)`；worker 进程内部 numpy/MKL 会各自默认吃满所有核 | `export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1`（**并发跑时收益最明显**） |
| 3 | 无头机器渲染依赖 | `multiagent/rendering.py:18` 需要 pyglet；训练不渲染，但 import 链可能需要 libGL | `apt install -y libgl1 libglib2.0-0` |
| 4 | **仓库没有 requirements.txt** | 全仓 glob 无结果 | 用 `requirements-linux.txt`（本次新增） |
| 5 | 配置注释必须独立成行 | ConfigParser 不支持行内注释 | 生成/修改 config 时遵守 |
| 6 | 跑完自动关机 | 省钱关键 | `python main.py xxx.txt; /usr/bin/shutdown` |
| 7 | **Windows 检出会把 `\n` 变成 `\r\n`** | 用 scp/网盘把 `.sh` 传到 Linux 会 `bash: $'\r': command not found` | 已加 `.gitattributes`（`*.sh text eol=lf`）；若仍中招：`sed -i 's/\r$//' scripts/*.sh` |

### 6.2 待服务器冒烟确认的（有风险，给现成修法）

| # | 风险 | 症状 | 修法 |
| --- | --- | --- | --- |
| 1 | **Linux 默认 `fork` 起 worker**，Windows 是 `spawn`（`env_wrapper.py:146` 用 `Process`，且全仓**从未调用** `set_start_method`） | worker 卡死 / `Cannot re-initialize CUDA in forked subprocess` | **已核实顺序：`main.py:2095` 建 env → `main.py:2128` 建 MASAC**，即 fork 发生在 CUDA 初始化之前 ⇒ 风险低。若仍报错，改 `utilities/env_wrapper.py:145` 为 `set_start_method('spawn', force=True)`（代价：worker 重新 import，启动变慢） |
| 2 | 显存能塞几个进程 | 第 3/4 个进程 CUDA OOM | 用 `scripts/bench_server.sh` 实测，别猜 |
| 3 | gcc/编译依赖 | 某些包无 wheel | 优先用平台自带 PyTorch 镜像 |

### 6.3 部署步骤

```bash
git clone https://github.com/lyy20/RLforUSV_COLREGS.git && cd RLforUSV_COLREGS/USV_COLREGS
export USV_LOG_ROOT=/root/USV/logs
bash scripts/server_bootstrap.sh          # 装依赖 + 冒烟 + 落盘环境快照
```

### 6.4 断点续跑（用抢占式的前提）

`POLICY_SAVE_INTERVAL` 每 N 回合存 `episode_last_<n>.pt`；重启时把配置里 `PRE_TRAINED=true` 即可从 `model_dir` 里最新断点继续。
**上线前必须先验证一次"跑 2k 回合 → 杀进程 → 重启 → 回合数接续"**，否则抢占式不能用。
